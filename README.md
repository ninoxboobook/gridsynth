# gridsynth

## What does the energy grid sound like?

Gridsynth is a proof of concept/art project inspired by the generative music of Brian Eno.

Gridsynth takes energy grid data from the [National Electricity Market](https://aemo.com.au/en/energy-systems/electricity/national-electricity-market-nem/data-nem) and turns it into a replayable song that also tells a story about energy demand and supply. That is, by listening to a gridsynth-generated song, we can also understand a little bit about what was going on with the electricity grid at a particular point in time.

[Listen to gridsynth](http://rihanari.es/gridsynth/) (best with headphones)

Gridsynth uses Tone.js and p5.js. 

You can find more information on how the song 'Victorian Energy Grid - June 11, 2021' was created down below.
## Building gridsynth
### Time
Each note you hear played by gridsynth corresponds to a five minute interval. Each song is 24 hours on one region's electricity grid, starting at midnight. The original proof of concept is the Victorian electricity grid on June 11, 2021.
### Tempo
The tempo (speed) of the song is determined by the scheduled demand in MW. So, as energy demand on the grid increases, the song speeds up; as it decreases, the song slows down. This allows you to hear how energy demand ramps up to periods of peak demand throughout the day.
### Instruments
Each fuel/generation source is assigned its own unique instrument.

* Coal generation is represented by a sine-wave oscillator with a long attack, creating a note that sounds a little like a "whomp".
* Wind generation is represented by a sine-wave oscillator passed through a ping-pong delay, creating a note that has a cascading echo which introduces some interesting syncopation.
* Gas generation is represented by a frequency-modulated synth that is passed through a chorus, creating a note that is quite sharp and tinny.
* Hydro generation is represented by a sampler that plays a piano sample that is also passed through a chorus.
* Solar generation is represented by a sampler that plays a cello sample.
* Battery generation is represented by a sampler that plays a French horn sample.
### Volume
The volume of each instrument is determined by the proportion of total scheduled and semi-scheduled demand that a generation source represents at a given time.

For instance, if coal generation represents 50% of the total scheduled and semi-scheduled demand at 11:15AM, the volume in decibels of the 11:15AM note will be 50% of gridsynth's volume range in decibels (this is currently slightly inaccurate, since decibels are logarithmic and me no math good).

In this way, you can hear the fuel mix of the energy grid.
### Melody
The pitch of each note for each instrument is generated by an algorithm that takes the generation in MW of a specific generation source at a given time, adds some noise, and then converts the fourth decimal of the natural logarithm of that number into a pitch from a scale designated by me.

There's not a lot of rhyme or reason behind this algorithm other than it creates a nice sense of randomness while maintaining replicability (e.g. the same data set will generate the same song).

The octave of each note is determined by taking the generation in MW of a specific generation source at a given time and comparing it to the maximum generation in MW of that specific generation source. For instance, if hydro generation at 3:00PM is 80% of the highest hydro generation value, the octave assigned will be the equivalent of the fourth octave on an 88-key piano.

In this way, you can hear the peaks and troughs of generation of each generation source.

I have purposely offset the melody of each instrument by a 16th note, firstly to create a little more rhythmic interest, and secondly because as the song continues to loop, the melodies will gradually fall out of sync, creating new harmonies (see 'Music for Airports' by Brian Eno). It's not purely correct from a data representation point of view, but hey, that's art.
### Bass line
The bass line is generated by the spot price trend. It is represented by a sampler that plays a Tibetan singing bowl. If the spot price is trending up, the bass line plays a note higher than the note it previously played; if the spot price is trending down, the bass line plays a note lower than the note it previously played. It the spot price trend is level, it plays the same note.

The spot price trend is worked out for each hour, and each hour is played as four bass notes (one for every three five minute intervals), so the bass line stays in step with the melodies.
### Visualiser
Finally, the gridsynth visualiser is painting a continuously updating graph of fuel mix (the inner circles) and total scheduled and semi-scheduled generation (the outermost circle). This information is already represented in the music; I just think it looks neat.
### Changing the sound
Everything above describes the original sound, which is what gridsynth always starts with. The Sound panel on the page lets you change it while the song plays:

* the key and the mode (the original is C Ionian), and which positions in the scale the melodies and the bass line use
* the slowest and fastest tempo, on one slider with two handles
* mute, solo and level for each voice (level is added on top of the volume that comes from the data)
* the wave shape and envelope of the three synth voices (coal, wind and gas), plus the harmonicity and modulation of the gas synth

The data still drives the song: demand sets the tempo within the range you choose, and the fuel mix sets the volumes. Changes are not saved, so reloading the page goes back to the original sound. The settings and their original values are in `js/settings.js`.

### Data
Gridsynth plays one day of grid data for one region at a time. Each day is stored as a JSON file in the `data` folder, and `data/index.json` lists the regions and days that appear in the pickers on the page.

The original song, 'Victorian Energy Grid - June 11, 2021', uses data from AEMO. Its demand, spot price and total generation are five minute values, but its fuel mix is hourly, so the value for each generation source repeats across the hour.

The more recent days come from the [Open Electricity](https://openelectricity.org.au) API (formerly OpenNEM), where every value is a five minute value. You can now hear the difference between, say, a summer day in SA and a spring day in NSW. For these days, total generation is the sum of every generating fuel source in the region, and battery generation is battery discharging.

#### Adding more days
You'll need Node.js 18 or later and a free API key from the [Open Electricity Platform](https://platform.openelectricity.org.au). Then run the fetch script with a date, or a date range:

```
export OPENELECTRICITY_API_KEY=your-api-key
npm run fetch-data -- 2026-01-15
npm run fetch-data -- 2026-10-01 2026-10-07
```

This fetches the day for every region: New South Wales (`NSW1`), Queensland (`QLD1`), South Australia (`SA1`), Tasmania (`TAS1`), Victoria (`VIC1`) and Western Australia (`WEM`). To fetch one region only, add `--region`, for example `--region SA1`.

Each region's day is saved to the `data` folder and added to `data/index.json`, which is what fills the region and day pickers on the page. The `default` value in `data/index.json` sets which song is loaded first.

The script is careful with API requests, since the free plan has a daily limit. Visiting the site never uses any: the page only reads the files in the `data` folder.

* One request returns every region in a network, so each block of up to seven days uses four requests for all regions (two for the National Electricity Market, two for Western Australia).
* Days that are already in the `data` folder are not fetched again. Add `--force` to fetch them again.
* If a run would need more than 20 requests, the script stops before making any. You can raise this with `--max-requests`.
* The script reports how many requests it made when it finishes.

Only complete days can be fetched, and the free plan covers the last two years.

#### Fetching new days automatically
The GitHub Actions workflow in `.github/workflows/fetch-data.yml` runs every morning and commits the previous day for every region, using four API requests a day. To turn it on, save your API key as a repository secret named `OPENELECTRICITY_API_KEY` (Settings, then Secrets and variables, then Actions). The workflow runs from the default branch, and it can also be started by hand from the Actions tab.

The workflow runs the fetch script with `--last 3`, which fetches the three most recent complete days. That fills in any day a previous run missed, at no extra cost in API requests. Days are kept for good, so the list of days grows by one each day.

The workflow commits straight to the default branch, so that branch must allow pushes without a pull request.

If you would rather keep a rolling window, add `--keep-days 30` to the command in the workflow. Days fetched with that option are removed again once they are more than 30 days old; days fetched without it are never removed.

### Deploying to GitHub Pages
The workflow in `.github/workflows/deploy-pages.yml` publishes the site to GitHub Pages whenever `main` changes, and again after each daily data fetch. GitHub Pages has to be turned on once: go to Settings, then Pages, and set Source to "GitHub Actions". Until then the workflow finishes without deploying.

### Running gridsynth locally
Gridsynth is a static site, but it needs to be served by a web server to load its samples and data. Run `npm start` and open http://localhost:8080.

Tone.js and p5.js are bundled together in `js/main.js`. To rebuild the bundle, run `npm install` and then `npm run build:vendor`.
